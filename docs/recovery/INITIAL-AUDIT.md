**Specific candidate-branch defects**

- **main-fixed: unconditional administrative password reset.** DevPasswordSeeder is a Component/CommandLineRunner with no dev profile or opt-in condition. It updates a named admin's password to a hardcoded value on every startup. This is a direct security regression if that branch is connected to a real shared database. Evidence: [DevPasswordSeeder.java:20](/tmp/authserver-audit/main-fixed/src/main/java/com/chellavignesh/authserver/config/DevPasswordSeeder.java:20). Remove or explicitly constrain this mechanism before considering any adoption. Its useful local pepper/key changes also require compatibility review against real password hashes.
- **main-fixed: deployment still depends on the source tree.** CMS is configured as `src/main/resources/cms`; a packaged JAR launched elsewhere cannot rely on that path. Only one login view was added; recovery/MFA/profile view targets remain absent. Three called procedures still have no definition: Client.GetSecrets, Partner.GetCertificatesByCertTypeId, Token.GetTokenByClientId.
- **main-test: no empty-database migration.** Its first versioned migration is V2, which immediately alters Token.AuthSession; there is no V1 schema creation in the configured location. Baseline-on-migrate does not manufacture those tables. Its repeatable still overwrites Client.CreateApplication with the old six-parameter signature. Evidence: [V2__AddMissingSchemaChanges.sql:10](/tmp/authserver-audit/main-test/src/main/resources/db/migration/V2__AddMissingSchemaChanges.sql:10), [R__AuthDBProcs.sql:308](/tmp/authserver-audit/main-test/src/main/resources/db/migration/R__AuthDBProcs.sql:308).
- **main-test: generated procedure bodies break isolation and mapper contracts.** GetUserByUsernameAndBranding and GetUserCredentialsByUsernameAndBranding accept branding but omit it from WHERE. They replace the standalone SQL's actual ExternalSource join/filter with unscoped username lookup. Several user queries return p.*,c.*,po.* rather than the explicit aliases UserDetails needs. Person.CreateMetadata requires five parameters but Java's create loop supplies three. These need semantic review, not just “procedure exists” checks. Evidence: [V5__AddMissingStoredProcedures_Part3.sql:125](/tmp/authserver-audit/main-test/src/main/resources/db/migration/V5__AddMissingStoredProcedures_Part3.sql:125), [V5__AddMissingStoredProcedures_Part3.sql:602](/tmp/authserver-audit/main-test/src/main/resources/db/migration/V5__AddMissingStoredProcedures_Part3.sql:602), [V4__AddMissingStoredProcedures_Part2.sql:281](/tmp/authserver-audit/main-test/src/main/resources/db/migration/V4__AddMissingStoredProcedures_Part2.sql:281).
- **main-test: the login/frontend protocol is incompatible.** Its Thymeleaf form submits a raw password, while KPCVPasswordEncoder Base64-decodes the form value. NextAuth directly POSTs /login without the OAuth saved request/branding and considers any final HTTP-OK response a successful identity; redirects to a rendered error page can therefore be mistaken for frontend login success. It does not obtain the bearer claims required by the backend permission evaluator. Its shared Axios client stamps x-request-datetime at construction, so a long-lived client sends an increasingly stale timestamp. Evidence: [auth.ts:32](/tmp/authserver-audit/main-test/frontend/auth.ts:32), [client.ts:11](/tmp/authserver-audit/main-test/frontend/lib/api/client.ts:11), [login.html:92](/tmp/authserver-audit/main-test/src/main/resources/templates/pages/login/login.html:92).

**Recovery order and acceptance gates**

1. **Preserve main and capture the existing environment.** Before repair, record the actual launch command, environment overrides, installed private-library versions, SQL Server schema/procedure definitions and Flyway history. Back up any database used for a later migration. This audit did not access that database.
2. **Make a clean build and an isolated environment reproducible.** Resolve the private artifacts, pin a supported JDK/Maven combination and document SQL Server/Redis requirements. ./mvnw currently has mode 100644, so direct invocation fails with permission denied; `sh mvnw` is a workaround, not a replacement for a proper executable wrapper. Unconditional external AuthClient factories are wired with blank default URLs/IDs/secrets; establish an explicit local integration mode rather than claiming those integrations work.
3. **Choose one database contract.** Reconcile the supplied schema, enums/seeds, all 132 call sites, argument order/count/types, output aliases and consumption/expiry semantics. Add a versioned fresh-install path and a tested upgrade path. Do not enable a pile of generated procedures against the shared DB as the first repair.
4. **Repair the complete identity path.** Correct MapStruct generation, hash prefix/pepper handling, base/context URL, branding, CMS, templates and login form encoding. Acceptance: create user → successful login → wrong password rejected → profile lookup → password change → old password rejected → new password accepted.
5. **Repair OAuth/security state.** Enforce MFA and active tokens; make issuance atomic; preserve refresh, scopes and consumed codes. Acceptance: code+PKCE exchange, code replay rejected, refresh/rotation, expiry rejection, logout rejection, pending-MFA code issuance rejected, tenant separation, recovery-token replay rejected, and concurrent code exchanges.
6. **Repair cache/session consistency and finish admin workflows.** Verify actual repository/serializer selection and cache hits as well as misses. Acceptance: repeated requests after login, another application instance, process restart, client/settings/secret changes immediately reflected, organization/application/credential/certificate/resource CRUD and redirect configuration.

Build the repair branch from main and selectively port reviewed changes. None of the inspected branches is qualified for deployment. A green compile, passing isolated probes, or complete procedure-name coverage cannot replace these acceptance gates.
